# Issue #3: V11.24 並び予想DOMの調査・試験記録

## 確認できた範囲

- Issue #3ではV11.24を貼り付けると複数レースは受信できる一方、「並び予想DOM未確認」のHOLDが報告されている。
- 利用者提供のiPhone版とPC版を元に、旧コードが見落とす構造の**架空DOM**を作成した。`racecard_footer-contents` 内の `p` 見出しと隣接要素に役割付き車番があり、その親領域に別の「オッズ」文字列がある場合、旧コードは `p` を見出し候補に含めず、広い領域の検査も除外する。旧コードの結果は `domConfirmed:false`、`lineSource:commentStrictFallback`、`validForPrediction:false` だった。
- 修正案は同じ架空DOMに対し、既知のフッター領域の `p` 等の見出しと隣接する役割列を対象にする。異なる候補が衝突した場合や、本文のみ・出所不明・領域不明の場合はHOLDを維持する。ラインは引き続き参考であり、サイトや正式ラインの真正性を認証するものではない。
- 元コードではコメント抽出の条件から「ジカ」「競り」単独が漏れる場合があり、検知処理へ渡らなかった。コメントを検出してHOLDとなる架空試験を追加した。

## 実資料に関する制約

この環境では公開ページの表示文字列を確認できたが、`keirin.kdreams.jp` への直接接続は403で制限され、生のDOMは確認できなかった。上記は**再現可能な原因候補**であり、Issue #3を引き起こした実ページの原因と断定できない。PC・iPhoneの実ページ、実iPhone Safari、実際の複数レースでは未試験。実ページの原文、実選手の情報、認証情報はテストやリポジトリに収録していない。

## 実装・安全条件

- 同一オリジンのKドリームスのレース詳細URLを検査し、別レースへのリダイレクトは拒否する。
- 新たに対応する見出しタグは既知のフッター内に限定する。本文やコメントから再構成したラインはDOM確認済みにしない。DOM候補同士が異なるときはHOLDする。
- 競り・ジカ、同一選手への複数番手、車番の欠員・重複、別ライン参照、曖昧な氏名参照などは従来どおりHOLDする。データの申告だけで独立照合や利用許諾を認証しない。
- 抽出結果に改訂識別子と診断文字列を付け、RaceLabの折りたたみ欄で見出し数・候補・役割列・欠員・重複・分類を確認できる。表示はエスケープする。実データを送信する機能は追加しない。
- iPhone向けに1〜12R、6〜12R、9〜12R、任意指定を用意した。範囲不正は送信せず、オッズは取得しない。
- 従来の38分割本体のSHA-256を更新し、旧Service Workerのキャッシュから新しい本体への更新とオフライン再起動を検証する。

## 再現試験

`node scripts/build-bookmarklets.cjs` で圧縮版を作成し、`node tests/bookmarklet-dom.cjs` を実行する。テスト対象のKドリームスURLはすべてPlaywrightが架空ページで応答し、実サイトには接続しない。iPhoneはChromiumの画面幅を模したもので、Safari実機ではない。`node --test tests/*.test.cjs` と `node tests/browser.cjs` で受信・安全条件および従来機能を確認する。

## Draft解除前の確認

権限を持つ利用者の環境で、実ページの並び見出し・フッター・役割付き車番のタグと親子関係を確認し、問題のレースと他のレースで診断と表示を突き合わせる。選手名、アカウント情報、Cookie、未許諾のページ原文やオッズは共有しない。ブラウザの実DOMが異なれば、その構造を基にテストを追加して安全に対応する。PCとiPhone Safariの実機確認が終わるまで、本調査版の実サイト互換性は未確認とする。
