# RaceLab V11.1｜共通計算入力の是正（Issue #18）

## 今回の確定した原因
共通HTML V11は、元統計行 `entries[].raw` が厳密照合できる場合に構造ライン候補のBANK参考計算を使い、照合に失敗すると無告知に異なる上位12点モデルへ切り替えていた。これにより、同じレースでも旧iPhone抽出JSONの形によって買い目が変わり得る。

## 分離して保管した検証版
2026-11-18に作成した `racelab_shared_v11_1.html` は、構造化統計だけから全端末に同じ参考モデル入力を組む。旧V11を上書きしない。

- HTML SHA-256: `d0b586edf0bd2d0d30778bd96eced240f344871a938a4e81b275c02037a2b58d`
- Scriptable起動ファイル: `RaceLab_Shared_V11_1.js` （同一HTMLを開くだけ）
- ZIP: `racelab_shared_v11_1.zip`
- R3正式Scenario/Pair・精度校正は**未実装**
- BANK参考計算で使う決まり手件数は同一レース内最大値による実験的相対化。実績率・校正済み確率と混同しない。
- ガールズは単独・固定ラインなしで参照する。
- 既存のPC V9.3・iPhone V10.1・共通V11は保護。

## 検証履歴
実際の四日市2026-11-13 5–12R（6車2R、7車6R）を用いて、元データとraw除外データでChromium PC幅/スマホ幅を比較し8/8一致（予想券集合、券数、1着参考頻度）。統計値を欠落させると自動フォールバックせず理由を表示することも確認。ブラウザ検証でありiPhone実機は未検証。
